## 2. Before you propose or record a task

- Keep it short and simple. Do less, but make it mouse and speech oriented. Target roughly 15 to 25 minutes of script time, because real video runs about 1.6 to 1.7 times the script.
- Use only apps that are not banned. The current list is in App_Policy.md (effective 16 Oct 2026). Word, PowerPoint, Excel, Terminal, Chrome, Safari and Preview are allowed, but pick an alternative when practical. Notes.app and TextEdit cannot display the opening Goal document.
- Use genuine apps that each do real work. One app is the minimum; 2 to 3 are suggested, not required.
- Keep typing below 20 percent of the video. Pre-fill templates and use helper functions so each typed burst is short.
- Make every input file before recording. No personal information in any of them.
- Write the Goal once, then paste that exact text into Studio, TaskRecorder, the opening note and the Metadata.rtf Request.
- Do not put anything in the approved text that the video will not show. If you shrink the task, change the Studio text first.
- Never read the Goal aloud. The only intro line is: "I will be beginning my task soon. Here is the workflow I have in mind."

## 3. Desktop and tool checklist (before Start Recording)

- Dock on the left or right edge.
- Clock shows seconds.
- At least one real UI change is made (built-in wallpaper, dark mode, accent colour, Dock size, sidebar icon size, resolution or in-app theme). Dock position does not count.
- Default cursor size and colour.
- Accessibility Inspector running, its window closed.
- Insightful minimized (only if you are hourly-paid; never show its window). Do Not Disturb on. Finder closed. Mac plugged in. Desktop cleared.
- Dock set to left or right, auto-hide off, indicators for open apps on.
- Window set to Fill, never Full Screen.
- All apps launched and minimized before Start. Only the opening note is visible.
- TaskRecorder 2.4.4: no sign-in needed, permissions green, microphone on, apps entered correctly.
- PII sweep: top right corner of Word, PowerPoint and VS Code, the Finder sidebar, and every Save or file window show no name, photo or email.
- **Enlarge the TaskRecorder window until the whole Task Description is visible.**
- Warm up Python: run a dry run in a temporary folder just before recording, so the first cell on camera does not take a minute to load.
- Do a 1 minute audio test and a typing speed test.

## 4. While recording

1. **Pause 1 second after every click.**
2. For every action say what, where and why. Name the real control and its place on screen.
3. Narrate every scroll and say where you stopped.
4. Speak slowly. Fewer words, clear pauses. Stay under 220 words a minute.
5. Say every keyboard shortcut aloud: "Command plus S to save".
6. Keep each typing burst short, about 25 to 30 seconds. No typing, pointer idle time or audio gap over 45 seconds. Aim for under 20 seconds of stillness.
7. When a cell or app is loading, keep talking and move the pointer along what it contains. Do not sit silent.
8. Never say "here" or "this" alone. Never mention personal information. Never narrate TaskRecorder.
9. At the first use of each prepared input (the CSV, starter and template files), say what it contains, why it is there, and that it is CC0 or public domain. Do not name how it was made.
10. After the work is saved, give the epilogue (target 3 to 4 minutes, maximum 4:00, six topics), then stop recording silently.

## 5. Keep the description, Goal and recording in step

The AutoQC "recording shows every part of the described task" check compares the video against the description in Studio.

- Open the Studio Prompt/Description field and read it line by line before recording.
- Every promised chart, check and output file must appear on screen, or be removed from the text first. If you cut scope, submit a change request so Studio matches.
- If the text says "PowerPoint and PDF", show the PDF export. If it says "charts of distributions", draw them.
- If a finding is still advice-level and accurate, use Comment and a Reviewer note. Use Dispute only when the checker is genuinely wrong.

## 6. After recording

- Wait until TaskRecorder shows Idle (Stopping, then Archiving, then Idle).
- Check the video length is between 15:00 and 50:59 including the epilogue (reviewers may accept up to 54:59, but plan for 50:59).
- Scrub the video for pointer stillness, long typing bursts and unclear audio.
- Use the `video.mp4` from the `recording_...` folder exactly as it is.
- Do not edit the deliverables after recording unless the change is trivial. The files should match what the video shows.

## 7. Deliverables.zip

- Name every file with spaces, not underscores: `input 1.docx`, `artifact 1.ipynb`, `final output 1.pptx`. Keep the extension.
- Inputs first, then artifacts, then final outputs.
- Include every input, intermediate file and final output. Do not include Metadata.rtf.
- Remove Mac junk. In Terminal: `zip -d "Deliverables.zip" "__MACOSX/*" "*.DS_Store"`. Then check with `unzip -l "Deliverables.zip"` from the folder that holds the zip (`cd ~/Desktop` first if it is there).
- If you rebuild the zip, use `zip -r -X "Deliverables.zip" Deliverables -x "*.DS_Store"`. Do not use Finder's Compress.

## 8. Metadata.rtf

- Topology: list every app visit in order, repeating an app each time you return to it. Use only LOOKUP, CREATE or MODIFY.
- Request: exactly the Goal, word for word.
- Task Description: a numbered, high-level outline naming the apps, key methods and the final deliverable.
- Delete the red example section at the bottom of the template.
- Upload it as its own file in Studio, separate from Deliverables.zip.
- The apps listed in Metadata.rtf must match the apps listed in Studio.

## 9. Studio and submission

- Upload four things: Metadata.rtf, the video (named `video.mp4`), the TaskRecorder zip (`recording_*.zip`) and Deliverables.zip. Tick the epilogue checkbox only if the recording includes the epilogue or the idea was first approved before 19 Oct 2026 6 PM PT. After submitting, the status reads Ready for Review.
- Final Notes must say exactly: "AI-generated before recording" for AI-made inputs.
- Run both AutoQC checks. Only Major flags block submission: fix or dispute each one. Minor flags are advice. A file or metadata problem needs a corrected upload and a re-run, not a re-record. Use Dispute only when you are sure the checker is wrong, with a written reason and a timestamp.
- Tick every manual check only after checking it against the recording.
- Go through the Workflow Checklist and the PII confirmation, then tick the final box.

## 11. Rule changes from the Oct 19, 2026 Writer Guidelines update

- **Accounts:** TaskRecorder 2.4.4 needs no sign-in, and assigned OTA accounts are retired. Use your @mercor.expert account or a new anonymised account for task apps.
- **Recorder account:** a separate Recorder Mac user is optional. Instead, clear the Desktop, use a built-in wallpaper, turn on Do Not Disturb, rename the Mac to something neutral, and run a 10-second test recording.
- **PII:** it is never tolerated. Reviewers most often find a name or photo in the PowerPoint or Word account corner, a username in a Save window or the Finder sidebar, and a name near the end of the video.
- **Apps:** the approved-app requirement is retired; check App_Policy.md for banned and limited-use apps. One app is the minimum.
- **Epilogue:** required for ideas first approved at or after 19 Oct 2026 6 PM PT. Cover completion and outcome, approach and key decision, challenges and problem solving, quality assessment, reflection and improvement, and insight. Target 3 to 4 minutes, maximum 4:00, and 3 minutes is not a minimum. The mouse may stay still.
- **Length:** writers plan 15:00 to 50:59 including intro and epilogue.
- **Window overlap:** about 25 percent covered for more than 6 seconds counts.
- **Reviewer tolerances (do not plan to these):** silence up to 60 seconds, typing up to 25 percent (35 percent for coding and content and writing), video up to 54:59, and a missing epilogue does not block approval.
- **Contacts:** ask Loki first; technical issues go to #odin--helpdesk.
